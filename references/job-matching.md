# 岗位匹配与推荐工作流（Job Matching）

当用户问「有什么岗位适合我 / 帮我推荐岗位 / 帮我找能投的简历岗位」时调用。数据源为**联网搜索**（研究级，非实时、不代投）。

## 1. 抽取简历画像
从简历/对话中抽取并保持以下字段：
- **目标岗**（如 党务专员 / 人事专员 / 党建岗 / 考公）
- **技能标签**（如 团员发展、人事数据治理、公文写作、Excel、合规审查）
- **城市**（如 山东 / 济南 / 菏泽 / 不限）
- **学历**（本科 / 应届 2026）
- **政治面貌**（中共党员 → 党务/国企/体制内岗是强加分项）
- **经验年限**（应届 / X 年）

## 2. 构造检索式
组合「岗位关键词 + 地区 + 批次 + 单位类型」，每组检索式独立发起搜索。示例（党务/HR 应届生）：
- `党务专员 招聘 2026 应届 山东`
- `国企 党建岗 校招 2026 中共党员`
- `事业单位 人事专员 招聘 应届生`
- `组织部 选调生 2026 公告`
- `基层 团务 社工 招聘 山东`

技术岗示例：
- `Java 后端 开发 招聘 2026 校招 上海`
- `前端 实习 转正 招聘 应届`

> 原则：每类目标岗跑 3–5 组不同检索式，覆盖「国企/事业单位/民企/体制内」多通道，提升召回。

## 3. 执行检索
用**联网搜索**逐组检索，收集结果中的：岗位名、单位类型（国企/事业/民企/政府）、地区、批次（校招/社招/选调）、政治面貌要求、学历要求、发布渠道。

## 4. 筛选与去重
- 仅保留**真实在招**、且画像匹配度 ≥ 阈值（建议 60%）的岗位。
- 去重（同一单位同岗合并），剔除明显过期/营销号内容。

## 5. 评分与排序
按四因子给匹配度（每项 0–25，合计 0–100，或标注高/中/低）：
- 岗位契合（技能/方向重叠度）
- 地区契合（城市/可接受 remote）
- 学历契合（是否达门槛）
- 政治面貌/身份契合（党员对党务/国企/体制内是强信号）

## 6. 输出推荐清单
对每条岗位，给出：
```
- 岗位：党务专员
- 单位类型：省属国企（某集团）
- 地区：山东·济南
- 匹配度：高（92）
- 为什么匹配：中共党员 + 有团务统筹经历 + 人事数据治理技能直接对口
- 简历微调建议：突出「台账/数据治理」量化；补「人事系统」关键词；求职信强调合规意识
- 投递渠道：单位官网招聘栏 / 国资小新公众号 / 智联
```
给出 Top 3–5 条，并附一句「如何进一步提升匹配」的总建议。

## 7. 边界声明（必须附在产出末尾）
- 结果属**研究级**：来自联网公开信息，**非实时库存**，可能漏掉部分在招岗位或含已截止信息。
- **绝不代投**：不代替用户提交任何申请；最终以官方招聘渠道（单位官网/人社局/官方公众号）为准。
- 建议用户把推荐清单当作「投递线索」，自行到官方渠道核验并在线投递。

## 进阶（可选）
若用户已连接招聘类连接器（如 大学生实习就业助手、报考决策），可将检索结果与该连接器结构化数据交叉验证，提升准确率；连接器未连接时，纯联网搜索即可运行。
