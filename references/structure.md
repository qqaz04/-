# 简历标准章节结构

两种成熟结构可任选其一，或融合使用。中文技术简历优先采用「中文程序员结构」；投递欧美岗位优先采用「通用（OpenResume）结构」。

---

## A. 中文程序员结构（源自 geekcompany/ResumeSample）

推荐顺序（逆序 = 时间倒序，最新的在最前）：

### 1. 联系方式（置顶，方便 HR 打印后联系）
- 手机：135********（外地手机可注明最优联系时间）
- Email：name@gmail.com（技术岗建议用 Gmail / 学校邮箱，慎用 QQ 邮箱）
- QQ / 微信号：可提供一个网络可达方式

### 2. 个人信息
- 姓名 / 性别 / 出生年
- 学历 / 学校 / 专业
- 工作年限
- 技术博客、GitHub（有原创 repo 的 GitHub 账号极大提升个人品牌）
- 期望职位、期望薪资、期望城市

### 3. 工作经历（按公司一级分组，公司内按项目二级分组，逆序）
每段需讲清：
- 你负责了哪些工作，在哪些地方做得出色 / 和别人不一样 / 成长快
- 最困难的问题是什么，采取了什么措施，最后结果如何
- 最自豪的技术细节是什么、为什么，实施前 / 后数据对比

> 每个公司写 2–3 个核心项目即可；项目过多则分类合并，每类选一个典型，其余一笔带过。

### 4. 开源项目和作品（证明工作以外能力的材料）
- 开源项目：列出 repo 与简要说明，Star / Fork 多的可注明
- 技术文章：自己写或翻译的文章（翻译可侧证英文技术文档阅读能力）
- 演讲和讲义：代表公司在技术会议的演讲、内部分享

### 5. 技能清单
- 分类列出熟练技能（语言、框架、数据库、工具链、云与平台等）
- 参考 `skill-keywords.md` 从目标 JD 抽取 5–10 个高频关键词写入

### 6. 致谢（可选）
- 简短一句：感谢阅读，期待共事。

## B. 通用结构（OpenResume 美式最佳实践）

核心四章，单栏、无照片、不含 references：
1. **Profile / Summary** — 2–3 句概括定位与核心优势
2. **Work Experience** — 逆序，每条以强动词开头、量化结果
3. **Education** — 学校、专业、学位、时间
4. **Skills** — 按类目列出，与 JD 对齐

> 美式规范刻意排除：照片（避免偏见）、References（另行提供）、双栏布局（双栏不利于 ATS 解析）。

---

## 章节写作要点（通用）

- **经历描述 = 动词 + 动作 + 量化结果**，而非职责罗列。
- **每节标题用标准词**（工作经历 / 教育背景 / 技能），避免花哨标题导致 ATS 误判。
- **日期统一格式**（如 2022.03 – 至今），逆序排列。
- **控制长度**：1 页（应届 / 初级）到 2 页（资深），重点突出近 3–5 年。
